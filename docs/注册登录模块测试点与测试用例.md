# 注册登录模块测试点与测试用例

> 依据 `http://localhost:8000/openapi.json` 设计，仅覆盖注册、登录及为验证登录 Token 所需的基础鉴权。本文档只做测试设计，不执行接口请求，不包含自动化脚本、测试报告或缺陷报告。
>
> 管理员账号 `admin@ecommerce.com`，口令以 `${ADMIN_PASSWORD}` 表示，**仅限本地测试环境**并由环境变量注入；文档不保存明文口令。
>
> 所有邮箱、姓名、密码均为测试数据；示例邮箱中的 `20261124` 为设计批次标识，执行时应确认邮箱未被注册，必要时替换为带时间戳的唯一值。

## 2. 接口契约摘要

### 2.1 注册接口

- 方法与路径：`POST /api/v1/auth/register`
- 鉴权：无。OpenAPI 未对该操作声明 `security`，注册接口按公开接口设计。
- 请求头：`Content-Type: application/json`；建议同时发送 `Accept: application/json`。
- 请求体：必填，`application/json`，结构为 `RegisterRequest`。

| 字段 | 必填 | 类型 | 格式/约束（文档原文） | 说明 |
|---|---|---|---|---|
| `first_name` | 是 | string | 无 `minLength`、`maxLength`、`pattern` | 名字 |
| `last_name` | 是 | string | 无 `minLength`、`maxLength`、`pattern` | 姓氏 |
| `email` | 是 | string | `format: email`；无长度约束 | 注册邮箱 |
| `password` | 是 | string | 无 `minLength`、`maxLength`、复杂度约束 | 登录密码 |
| `phone` | 否 | string 或 null | 无格式、长度约束 | 可省略或显式传 `null` |

请求示例：

```json
{
  "first_name": "Qa",
  "last_name": "Register",
  "email": "qa.reg.p0.001.20261124@example.com",
  "password": "Qa!Passw0rd#2026",
  "phone": "13800138000"
}
```

响应约定：

| 状态码 | 文档定义 | 响应结构 |
|---|---|---|
| `201` | Successful Response | `application/json`，通用 object，`additionalProperties: true`，未定义具体字段 |
| `422` | Validation Error | `HTTPValidationError`，含 `detail` 数组，数组元素为 `ValidationError` |

`ValidationError` 必填字段：`loc`、`msg`、`type`；可选字段：`input`、`ctx`。其中 `loc` 为字符串/整数数组，通常用于定位出错字段。

### 2.2 登录接口

- 方法与路径：`POST /api/v1/auth/login`
- 鉴权：无。OpenAPI 未对该操作声明 `security`，登录接口按公开接口设计。
- 请求头：`Content-Type: application/json`；建议同时发送 `Accept: application/json`。
- 请求体：必填，`application/json`，结构为 `LoginRequest`。

| 字段 | 必填 | 类型 | 格式/约束（文档原文） | 说明 |
|---|---|---|---|---|
| `email` | 是 | string | `format: email`；无长度约束 | 登录邮箱 |
| `password` | 是 | string | 无长度、复杂度约束 | 登录密码 |

请求示例：

```json
{
  "email": "admin@ecommerce.com",
  "password": "${ADMIN_PASSWORD}"
}
```

响应约定：

| 状态码 | 文档定义 | 响应结构 |
|---|---|---|
| `200` | Successful Response | `application/json`，通用 object，`additionalProperties: true`，未定义 Token 字段名、类型和过期时间 |
| `422` | Validation Error | 同注册接口的 `HTTPValidationError` |

### 2.3 基础鉴权与公共约定

| 项目 | 文档信息 |
|---|---|
| 全局 `security` | 未声明 |
| 鉴权方案 | `HTTPBearer`，`type: http`，`scheme: bearer` |
| 需要 Bearer Token 的接口 | 例如 `GET /api/v1/auth/me`，声明 `security: [{"HTTPBearer": []}]` |
| `servers` | 文档未配置；测试地址采用任务给定的 `http://localhost:8000` |
| 已定义失败响应 | OpenAPI 仅定义 `422`；本版按 HTTP 语义补充 `400`、`401`、`409`、`415` |
| 成功响应字段 | 注册/登录为通用 object；登录响应必须包含可提取的 Bearer 凭证 |

> Token 约定：登录成功必须返回可用于 `Authorization: Bearer <token>` 的凭证，不限定具体字段名；未携带、格式错误或无效 Token 访问 `/api/v1/auth/me` 必须返回 `401`。

### 2.4 无需求文档下的判定约定

OpenAPI 未逐项定义的细节，本版统一按 HTTP/REST 语义、接口最佳实践和基础安全常识固定预期：

1. 请求体字段缺失、类型错误、格式非法、空值或弱密码，返回 `422` 并给出明确字段错误；
2. JSON 语法错误返回 `400`；非 `application/json` 媒体类型返回 `415`；
3. 重复邮箱注册返回 `409`，不得创建第二个账号；
4. 错误密码、不存在用户、空密码登录返回 `401`，错误信息不得区分账号是否存在；
5. 未认证、错误鉴权方案、无效/篡改 Token 访问受保护资源返回 `401`；
6. 成功登录必须返回可用的 Bearer 凭证；成功响应不得包含明文密码或哈希；
7. 额外字段应被忽略，不得通过请求中的 `role` 改变用户角色；
8. 邮箱按主流实践做大小写不敏感和首尾空格归一化；
9. 注册接口中的 XSS/SQLi 字符串按数据处理；登录密码注入按认证失败 `401`；登录邮箱注入按格式非法 `422`；均不得导致 `5xx`、SQL 执行或未编码的 HTML 输出；
10. 明显超长邮箱、1 位弱密码等异常输入返回 `422`，不臆造具体长度上限。

## 3. 测试设计说明

- **正向用例合并**：同一正常流程、同一前置条件、无冲突的校验点放在一条用例内一次覆盖。`TC-REG-001` 覆盖注册成功、响应脱敏、公开接口和可选 `phone` 省略/`null`，并继续验证新账号登录；`TC-LOG-001`、`TC-LOG-002` 覆盖登录成功、响应脱敏、Token 提取和 `/me` 鉴权。
- **负向用例单一变量**：每条负向用例只引入一个错误变量，其他字段保持合法。同一字段的多个非法值可以作为一个用例的数据组，例如多个非法邮箱格式；不同字段的错误不混在一条用例中。
- **等价类与边界值**：合法/非法邮箱、`phone` 省略/`null`/错误类型；明显超长邮箱和 1 位弱密码应被拒绝。
- **必填校验**：四个注册必填字段和两个登录必填字段分别拆分，便于定位具体字段。
- **业务异常**：重复注册、错误密码、不存在用户、空密码。
- **基础安全**：额外字段提权尝试、XSS/SQLi 字符、响应敏感信息、未授权/伪造 Token 访问受保护接口。
- **优先级**：P0 为核心主流程或阻断性问题；P1 为重要异常和边界；P2 为次要探索性校验。
- **预期依据**：`201/200` 成功语义、`400/401/409/415/422` 失败语义、OpenAPI 字段结构及基础安全常识；实际行为不符合即判错。所有用例均额外要求不出现 `5xx` 服务端错误。

## 4. 常理判定依据

| 判定项 | 明确预期 | 判定依据 | 影响用例 |
|---|---|---|---|
| 参数缺失、类型错误、格式非法、空值、弱密码 | `422`，包含 `detail` 和字段定位 | 请求体 schema 校验与基础输入安全常识 | TC-REG-002、TC-REG-004 至 TC-REG-017、TC-LOG-005、TC-LOG-006、TC-LOG-008 至 TC-LOG-010 |
| JSON 语法错误 | `400`，包含明确语法错误信息 | HTTP 400 Bad Request 语义 | TC-REG-021、TC-LOG-014 |
| 非 JSON 媒体类型 | `415`，包含明确媒体类型错误信息 | HTTP 415 Unsupported Media Type 语义 | TC-REG-022、TC-LOG-015 |
| 重复邮箱注册 | `409`，包含“邮箱已存在”错误信息，不创建第二个账号 | 邮箱唯一性约束与 HTTP 409 Conflict 语义 | TC-REG-018、TC-REG-019 |
| 错误密码、不存在用户、空密码登录 | `401`，使用通用认证失败提示，不区分账号是否存在 | 认证安全与防账号枚举常识 | TC-LOG-003、TC-LOG-004、TC-LOG-007 |
| 未携带、错误方案、无效/篡改 Token | `401`，不返回受保护资料 | HTTPBearer 鉴权与 HTTP 401 语义 | TC-LOG-020、TC-LOG-021、TC-LOG-022 |
| 额外 `role` 字段 | 被忽略；注册 `201`、登录 `200`，角色不提升 | 防批量赋值（mass assignment）常识 | TC-REG-023、TC-LOG-016 |
| 邮箱大小写/首尾空格 | 归一化后登录成功 `200` | 主流邮箱输入处理惯例 | TC-LOG-011、TC-LOG-012 |
| XSS/SQLi 字符串 | 注册接口返回 `201` 并作为数据处理；登录邮箱注入返回 `422`；登录密码注入返回 `401`；不执行、不泄露 SQL、不返回 HTML | 输入安全与输出编码常识 | TC-REG-024 至 TC-REG-026、TC-LOG-017 至 TC-LOG-019 |
| 成功登录凭证 | 返回可提取的 Bearer Token，可访问 `/me` 返回 `200` | HTTPBearer 鉴权语义 | TC-REG-001、TC-LOG-001、TC-LOG-002、TC-LOG-022 |
| 成功响应敏感信息 | 不包含明文密码、哈希、盐值 | 凭据保护常识 | TC-REG-001、TC-LOG-001、TC-LOG-002 |
| 超长邮箱、弱密码 | `422`，包含字段错误信息 | 邮箱格式与密码强度常识 | TC-REG-016、TC-REG-017 |
